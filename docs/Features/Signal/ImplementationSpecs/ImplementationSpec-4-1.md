## Migration 5 and history model

Retain every original meeting field and existing meeting_tasks row. Add nullable `time_zone`, `show_in_day`, and `active_version_id` to meetings, plus `revision INTEGER NOT NULL DEFAULT 0 CHECK(revision>=0)`. Nulls are temporary legacy markers, not application defaults.

Create these additive tables with opaque text IDs, checked enums/nonnegative ordinals and appropriate foreign-key/index constraints:

| Table | Fields and authority |
| --- | --- |
| meeting_versions | id PK, meeting_id FK, created_at UTC; immutable configuration-version identity. |
| meeting_segments | id PK, version_id FK, from_ordinal, to_ordinal nullable exclusive, anchor_local (date/time including milliseconds), anchor_utc, time_zone, repeat_rule none/daily/weekly, repeat_until nullable inclusive series-local date, fold_policy earlier/later, title, duration_min, link_url, agenda_md, notes_md, reminder_min, show_in_day. Immutable complete payload for its ordinal interval. |
| meeting_segment_tasks | segment_id FK, task_id FK, composite PK; complete default links for that immutable segment. |
| meeting_occurrences | meeting_id FK, occurrence_key, ordinal, revision, cancelled 0/1, snapshot_json nullable, actual_starts_at nullable UTC, attendance unmarked/attended/missed, occurrence_notes_md, updated_at UTC; PK(meeting_id,occurrence_key), UNIQUE(meeting_id,ordinal). |
| meeting_occurrence_tasks | meeting_id, occurrence_key composite FK, task_id FK, composite PK; complete links whenever an occurrence has a snapshot. |
| meeting_cutoffs | meeting_id FK, from_ordinal, created_at UTC; durable cancellations; effective cutoff is MIN(from_ordinal). No edit removes one. |
| agenda_requests | request_id PK, payload_hash, outcome_json; replay tombstones without cascading business foreign keys. |

Index segment version/from ordinal, occurrences actual_starts_at and meeting/ordinal, both task-link lookup directions, and cutoffs meeting/from ordinal. A snapshot contains all effective MeetingFields EXCEPT task_ids, including actual UTC start/timezone and resolved local/offset values, and never contains executable SQL or arbitrary file paths. Validate snapshot JSON through a dedicated typed DTO excluding task IDs. Occurrence links come only from meeting_occurrence_tasks; inherited links come only from the effective segment's meeting_segment_tasks. Segment configuration is immutable; deletion may detach task links from historical segment/occurrence link rows. An occurrence snapshot may be replaced only by an explicit occurrence edit or the selected-target following-edit rule below, preserving its separate notes/attendance; passive projection and ordinary following edits never rewrite protected historical snapshots. Project deletion may remove the whole owned graph. Original meeting_tasks is a compatibility mirror of the current tail's defaults, never a read fallback; create/following changes synchronize it, and deletion detaches it alongside all authoritative link tables. Original meeting scalar fields may mirror current tail metadata, but never replace version/occurrence authority for historical reads.

`initializeAgenda(zone)` validates an IANA zone then uses one BEGIN IMMEDIATE transaction to initialize every meeting whose active_version_id is null. Create a first version/segment at ordinal 0 from the stored UTC instant converted into that zone; retain `anchor_utc` and original starts_at exactly, including seconds/milliseconds and a legacy fold's actual offset. Copy its links, agenda/notes and existing recurrence rule. Set show_in_day true, default fold policy earlier for subsequent generated slots, no recurrence end, unmarked attendance and no fabricated occurrence notes. Empty/new ordinary databases are valid. Repeat calls, including after workspace-zone changes, never alter initialized rows. Do not rewrite seed markers, fixture IDs or existing fields.

## Stable identity, segments and projection

`MeetingRef {meetingId:string,occurrenceKey:string}` is the only editor identity. Native occurrence keys encode the logical sequence ordinal (e.g. canonical `o:17`); treat them as opaque in JS. `MeetingOccurrence.id` is a stable SHA-256-derived text key of meetingId plus occurrenceKey; every ordinal including 0 uses that scheme. Preserve the original meeting id as ref.meetingId, not as the per-occurrence display key.

An immutable version holds a nonoverlapping ordered segment chain. A segment covers [from_ordinal,to_ordinal), generates ordinal n from anchor_local plus (n-from_ordinal) calendar days or weeks, and is independently limited by its inclusive repeat_until. For none, only its anchor ordinal exists. Dates skipped by a DST gap still occupy their ordinal: changing the fold/end rule cannot renumber later references. Slot 0/segment anchor uses its explicitly saved anchor_utc; later slots resolve saved wall time in the saved zone, skip gaps and select the segment's earlier/later fold policy. Duration is elapsed UTC minutes, 1–1440, never wall-clock subtraction.

For a following edit, create a new version with copied immutable prefix segments truncated at the selected ordinal and a replacement tail anchored at that ordinal. Copying produces new segment IDs but never new occurrence keys. Do not modify old versions. Preserve already stored snapshots/notes/attendance keyed by ordinal. Individually edited future occurrences retain their full effective fields and links even when new daily/weekly/none/end settings would no longer generate the original date or ordinal. The explicitly selected, not-yet-started occurrence is the edit target: replace its existing effective-field snapshot with the reviewed draft while preserving its separate attendance/occurrence notes and stable ref; retained future overrides means subsequent ordinals, not silently ignoring the selected edit. If the selected occurrence has already started, its historical payload is protected and the preview explains that only eligible following occurrences change. Preview enumerates preserved exceptions and explains ordinal-based continuity instead of implying all old dates follow the new cadence.

Protect past by actual start instant, not only original slot ordinal. Before replacing a tail, any generated occurrence within that tail whose actual start is before the native clock must remain unchanged; persist a complete snapshot if prefix preservation alone cannot protect it (for example the selected occurrence was moved forward while later ordinals have already happened). Existing recorded/overridden past snapshots remain untouched. Recording attendance or occurrence notes snapshots the complete current effective payload and links so subsequent cadence changes cannot move recorded history. Clearing attendance to Unmarked or clearing notes does not delete that snapshot.

Projection takes a validated half-open UTC interval and optional owning project. For each active segment, convert interval bounds into its zone, include a 24-hour lookback for maximum elapsed duration and offset transitions, then arithmetically seek the first candidate ordinal near the interval rather than walking from series inception. Generate only candidates in that small neighborhood and exact-filter `start < end && start+duration > begin`. Union snapshot rows selected by actual_starts_at intersection, including snapshots outside the active cadence/end. Deduplicate by MeetingRef, letting snapshot replace generated data. Apply individual cancellation and the series MIN cutoff to the union last; a moved exception cannot escape cancellation by moving across dates. Distinct refs at the same instant remain distinct.

Return skipped local dates as bounded diagnostics for the requested range. Finite query guards: day/week reads cover at most seven local dates, native Board requests at most eight elapsed days to allow DST, and a 10,000-occurrence ceiling returns a descriptive validation error rather than silent truncation. Detail by ref resolves one ordinal without enumerating history. Never materialize an unbounded future or create blocks.

## Shared DTO/read API

`domain/agenda.ts` exports MeetingRef; MeetingFields `{title,starts_at,start_local,start_offset,time_zone,duration_min,link_url,agenda_md,notes_md,reminder_min,show_in_day,task_ids}`; SeriesDraft extends it with `{repeat_rule:'none'|'daily'|'weekly',repeat_until:string|null,fold_policy:'earlier'|'later'}`; and Attendance. start_local is canonical `YYYY-MM-DDTHH:mm:ss.SSS`; start_offset is the explicitly resolved numeric UTC offset. Native must verify that this local wall time, offset, IANA timezone and starts_at describe the same instant; nonexistent wall inputs cannot be silently normalized. MeetingOccurrence retains all original Meeting fields plus ref, revision (current series/root concurrency revision), start_local, start_offset, time_zone, show_in_day, attendance, occurrence_notes_md, project_name/project_color. Its starts_at and content are effective occurrence values; link targets come from current existing task records.

`AgendaQuery {date:string,timeZone:string,projectId?:string}` selects a local date; Week and related-meeting queries use its enclosing Monday–Sunday week. `AgendaTask` extends BoardTask with project_name/project_color and `planned_ranges:{date,start_min,end_min}[]` in the returned query calendar window. Define:

- `AgendaDay {date,tasks:AgendaTask[],meetings:MeetingOccurrence[]}`.
- `TodaySnapshot {query,today,week_start,days:AgendaDay[],overdue:AgendaTask[],due_today:AgendaTask[],tomorrow:AgendaTask[],meetings:MeetingOccurrence[],hours_this_week:{project_id,project_name,project_color,hours}[],counts:{overdue,due_today,tomorrow,meetings},fingerprint}`.
- `WeekSnapshot {query,today,project:ProjectRecord,week_start,days:AgendaDay[],later:AgendaTask[],no_date:AgendaTask[],overdue_before_week:AgendaTask[],overdue_counts:Record<string,number>,fingerprint}`; projectId is required for getWeek.
- `MeetingDetail {occurrence:MeetingOccurrence,series:{repeat_rule,repeat_until,fold_policy,revision},linked_tasks:AgendaTask[]}`.
- `TaskMeetingPage {task_id,week_start,range_start_utc,range_end_utc,occurrences:MeetingOccurrence[],previous_date,next_date}`.

`native/agenda.ts` invokes initializeAgenda(timeZone), getToday(query), getWeek(query), getMeetingDetail(ref), getTaskMeetings(taskId,query), searchAgendaTasks({text,limit,cursor?}), previewMeetingChange(change), and applyMeeting(input). searchAgendaTasks searches existing tasks across all projects; limit is 1–50, return `{items:AgendaTask[],nextCursor:string|null}` with an opaque keyset cursor and deterministic project/title/id order. Deleted task selection fails native validation; do not create tasks from search text.

Read snapshots share a single SQLite read transaction and one established native/fixture clock sample. Derive `today` from that instant in query.timeZone. getToday follows this actual day: normalize its reply query.date to today even if a midnight race made the incoming date stale; Task 4-3 must accept only the correctly keyed effective-day ticket and refresh its clock/selection. Week's query.date stays pinned for navigation; its separate today still uses the native clock. Date buckets use workspace-zone local dates; earlier time today stays Due today, and only calendar dates before today are Overdue. These three buckets exclude Done; strip/Week include Done. Week later means due date after Sunday, no_date means null, and older unfinished deadlines remain separately accessible through overdue_before_week. Per-day overdue_counts counts unfinished tasks in that day only when day<today. Hours this week sums completed time_entries.minutes/60 by start instant within Monday-to-next-Monday local boundaries; never add live timer elapsed. Planned ranges are actual block rows, not invented meeting assignments. Project scoping is consistent across every array/count. Overnight meetings appear in each intersected day, with unique Today count by ref and per-day rendering key ref+date.

Do not inject unbounded/calendar-dependent reads into generic `workspace::models::detail(conn,id)`, which also runs inside timer/task/planner writes. Return its legacy meetings field as an empty deprecated array and document this in TaskDetail. Task 4-3 replaces every task-detail linked-meeting display with getTaskMeetings and explicit previous/next-week controls; no raw fallback. Repeated edit refreshes fetch the currently selected related-meeting week with generation guards.

Extend workspace deletion graph/fingerprint to include all series versions/segments, occurrence state/cancellation/link rows and cross-project task-link detachments. Task deletion detaches that task from original meeting_tasks, all segment links and occurrence links, retaining meetings and history; affected surviving meeting roots bump revision. Project deletion deletes its owned meeting graph before meeting roots, but only detaches deleted tasks from other projects' meetings. A one-off meeting deletion removes owned meeting data/links, never linked tasks, task blocks, entries or sessions. agenda_requests outlive all these deletions so replay cannot recreate data. Include new graph contents in pre-delete fingerprints and roll back every change on failure.

## Mutations, previews and receipts

Use a discriminated `MeetingChange` union with these payloads:

```text
create           {projectId,draft:SeriesDraft}
edit_occurrence  {ref,expectedRevision,draft:MeetingFields}
edit_following   {ref,expectedRevision,draft:SeriesDraft}
record           {ref,expectedRevision,attendance,occurrence_notes_md}
remove           {ref,expectedRevision,scope:'one_off'|'occurrence'|'following'}
move_due         {taskId,dueAt:string|null,expectedRevision}
```

Represent each as `{action:<name>,payload:<shape>}`. Meeting ownership is selected at creation and remains read-only thereafter. No partial recurrence fields are accepted by edit_occurrence. Recurring removal sets cancelled or appends cutoff, never rewrites history as an ordinary root delete. Never reset a cutoff during subsequent edits. Following removal must reject a selected occurrence whose actual start is already past, and must reject if any effective occurrence at or beyond the proposed cutoff has an actual past start (including a lower-ordinal occurrence moved forward while later ordinals already occurred). Preview explains that historical occurrences would be affected and offers individual cancellation or selection of a later unaffected slot. Revalidate this protection against native now in the writer transaction. This preserves actual past while retaining the unconditional cutoff rule for every generated/overridden future; do not introduce an override loophole in cancellation filtering.

`previewMeetingChange(change)` validates read-only and returns `{fingerprint,affected_counts,preserved_overrides:MeetingOccurrence[],skipped_dates:string[],diagnostic_range:{start,end},warnings:string[]}`. Counts are finite affected stored records, not a fake infinity; an unbounded following operation is described by scope. Fingerprint covers normalized change, root revision, relevant versions/overrides/links and current protection boundary (the affected protected occurrence set, not raw ticking now/elapsed values). Require its exact fingerprint for edit_following and every remove. Recompute under the writer transaction; a changed graph returns Conflict for renewed review.

`applyMeeting({requestId,change,expectedFingerprint?})` returns `MeetingWriteResult {detail:MeetingDetail|null,outcome:{ref:MeetingRef|null,removed:boolean,task_id?:string},changed_details:TaskDetail[],affected_project_ids:string[],affected_task_ids:string[],revision:number|null,replayed:boolean}`. Canceled/deleted detail is null. A following edit may invalidate many queries; affected projects/tasks explicitly include old and new link owners for frontend cache invalidation. move_due returns changed_details and task_id, not a fabricated meeting ref.

At the command boundary sample the established native/fixture clock and clone the SQL-plugin pool. Core operations use BEGIN IMMEDIATE. Canonicalize and SHA-256 hash the request payload excluding requestId; check agenda_requests first, before current existence/revision checks. Same ID/different payload is Conflict. Exact replay reconstructs current detail/changed task state plus original outcome; missing/deleted targets return null/empty with removed state, never re-run creation. On a new request validate all fields/tasks, expected revision, preview fingerprint and calendar inputs; mutate; bump the root revision once for a real meeting change; build authoritative reply; persist receipt; then commit. Validation/reply/receipt failures proven rolled back before commit are known uncommitted AppErrors. A commit failure whose outcome cannot be proven, or a postcommit serialization/transport failure, must use UnknownOutcome (or equivalent unknown classification), never a blanket known Database error. Task 4-3 retains the exact request for replay and does not unlock resubmission as a new write. Receipt recovery determines whether commit occurred. Post-commit refresh failure is never reported as a failed write.

For move_due, use the existing scalar normalization/revision/bump/detail helpers inside this same transaction, not workspace::tasks::update's nested pool transaction. Only due_at may change; preserve status, blocked/done timestamps, orders, sessions, entries and planner rows. Same normalized instant is a no-op but still records its receipt. Deadline instant input is validated UTC; frontend conversion is not trusted to select a database or alter other fields.

## Precision-preserving calendar helpers

`agenda-calendar.ts` exports `proposeTaskDate(task,targetDate:string|null,zone)` returning either `{kind:'ready',due_at:string|null}` or `{kind:'confirm',date,time,choices:{offset,instant}[],reason:'no-deadline'|'gap'|'fold'}` and `resolveTaskDate({date,time,offset?},zone):string|null`. Time includes HH:mm:ss.SSS. resolveTaskDate returns null only when date and time are both empty; partially empty input is a validation error. A null target explicitly clears. No deadline proposes visible 17:00:00.000. Existing due dates convert directly through Temporal.Instant→ZonedDateTime; retain hour/minute/second/millisecond while replacing only the calendar date. An unchanged date preserves the exact original instant. Do not call minute-only deadlineFields. Repeated destination wall time requires explicit offset; nonexistent time requires a changed editor value, not an automatic shift. Preserve precision when an unchanged field is round-tripped through the confirmation editor.

Meeting start conversion follows the same explicit-zone/gap/fold rules for one-offs and occurrence edits. The editor submits start_local/start_offset alongside starts_at/time_zone; native parses the wall value without overflow, enumerates valid offsets in that zone, requires the selected start_offset to match one candidate, and requires that candidate's UTC instant to equal starts_at exactly at millisecond precision. A gap has no candidate and fails; a fold cannot pass without a matching explicit offset. Recurring future resolution uses the separately visible series fold policy. Inclusive end date cannot precede the anchor local date. Safe join URLs reuse native HTTP(S)/credential validation. Duration is a whole 1–1440 minutes; reminder is a nonnegative whole number; task links are unique existing IDs, including cross-project choices. No Join side effect changes attendance.
