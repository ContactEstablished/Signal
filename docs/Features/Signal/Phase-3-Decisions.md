## Approved decisions

| ID | Approved behavior | Why the decision matters |
| --- | --- | --- |
| D1 — Compact layout | Keep full content at three lanes; collapse to title and accessible detail at four or more. Focus uses neutral styling with a focus icon, not a project color. Keep the 26px minimum painted block height; pack lanes using painted extents for short blocks so adjacent 15-minute blocks do not cover each other. Scheduling still uses actual time intervals. | The handoff omits three-lane treatment and focus styling; its 26px minimum is larger than a snapped 15-minute interval at 60px/hour. |
| D2 — Automatic placement | Manual drag/move/resize allows intentional overlaps and stays within one calendar day. Automatic Quick add/carry/bulk placement avoids all projects' blocks and meetings, regardless of visible scope. Today starts at the next 15-minute boundary at/after now; a future date starts at 07:00. Automatic planning is disabled for past dates. Never spill into the next day; report items that do not fit. | Parallel manual work remains possible without automatic actions silently colliding with hidden projects or crossing midnight. |
| D3 — Block/timer lifecycle | Start from a task block associates a new session with that block. An existing task timer keeps its original association; expose it rather than starting another or moving its time. Completing a block with its own live timer asks to Stop and complete or Cancel. Moving its task to Done is a separate optional offer, never automatic. Removing a block preserves logged time and detaches any linked session/entry after a warning; it does not delete the task or stop its timer. | Requires explicit compatibility with M2's one-session-per-task, durable receipts and completed-entry accounting. |
| D4 — Leftovers | Carry unfinished task blocks from the preceding calendar day at their original planned length, even when some work was logged. Exclude tasks already Done. Preserve source links; each source can be carried only once, including repeated requests. Carry all uses source start time/ID order. Dismiss hides the banner for that destination date and keeps sidebar items available. Older dismissed/source blocks do not independently resurface on later days; an unfinished carried block can become the next day's leftover. | Resolves identical-length versus remaining-work copy, eligibility, repeat carry and reappearance. |
| D5 — Sidebar and totals | Due soon means unfinished tasks due by the end of the selected date's next six days, including overdue tasks. Unscheduled means unfinished tasks with no task block on the selected date. Drag-in uses positive remaining estimate rounded up to 15 minutes and capped at two hours; unknown estimate defaults to 30 minutes, exhausted estimate to 15 minutes for explicit drag. Planned sums block and meeting durations, counting parallel work separately. Logged sums completed entries whose start is on the selected local date. Blocks shows done/all non-meeting blocks. Project scope filters these lists/totals; neutral blocks stay visible. | Defines eligibility, missing estimates and parallel-work statistics without inventing additional tasks or counting running time as logged. |
| D6 — Empty-day planning | Plan from due dates previews due-soon tasks in due/priority/title/ID order, skips tasks already planned that date or with exhausted estimates, and uses D2/D5 durations/placement. Copy last Monday means the most recent Monday strictly before the selected date; copy task and neutral blocks at their original local times with done reset, preserving intentional overlaps. Meetings are not copied. Both actions preview before Apply, identify conflicts/no-space/skips, and are repeat-safe. | These buttons have no complete behavior in the handoff; copies need provenance separate from carry links. |
| D7 — M3 meeting boundary | Display read-only stored meeting instances from their own UTC timestamps/project colors, with existing safe external Join links. Do not duplicate meetings into blocks. Meeting editing, recurrence expansion and attendance remain M4; repeating metadata alone does not create extra M3 occurrences. | Keeps M3 bounded while explicitly identifying the remaining recurring-meeting behavior. |
| D8 — Calendar/timezone | Planner blocks retain local date/minute fields and follow the current workspace timezone; changing timezone keeps their displayed wall times. Meeting instants and completed entries convert into that timezone. Keep a fixed 24-hour visual grid. Reject scheduled block endpoints in nonexistent DST times; require an explicit offset choice for repeated times and persist that choice for later reminder consumers. Timer elapsed accounting remains UTC wall-clock time from M2. | Avoids silently choosing nonexistent/ambiguous scheduled instants while preserving the local planner schema contract. |

## Approved review refinement — September 13, 2026

The user requested quicker time editing and a date picker below Start/End. Add ±15-minute controls, 30/60/90/120-minute duration shortcuts, and an explicit destination date. Save moves the existing block, retaining its identity, task, completion/provenance, logged entries, and live timer association; it does not change the task due date. Creation may also target the chosen date. After confirmed save or exact retry, open the destination day. Revalidate calendar/DST endpoints for that date and clear stale offset choices whenever the date/time changes. Pointer movement remains within one day under D2; no interval crosses midnight. This refines the editor within M3 and leaves D1–D8 otherwise unchanged.

## Approved task split

1. **Task 3-1: planner domain and native persistence.** Pure lane/placement/carry helpers; block mutation/read contracts and additive migration where required; timer/block lifecycle integration and real database tests. Own new planner Rust/domain/DTO/native modules plus native registration/migrations/timer compatibility.
2. **Task 3-2: planner canvas and interactions.** Callback-driven grid, blocks, selection/task picker, drag/resize, keyboard/cancel states, reference styling and component tests. Own new planner presentation components; no independent database writes or global queue.
3. **Task 3-3: Your Day integration and planning workflows.** Date/scope/sidebar, Quick add/leftovers/bulk previews, shared Workspace queue and App wiring, native verification, documentation and final completion commit. Own YourDay view, planner state, existing App/workspace integration and shared tokens.

The three task/spec pairs and `Execution-3-Prompt.md` make this split executable. Production work follows the validated kickoff. Existing `blocks` local date/minute/kind/task/done/source fields and nullable `block_id` in M2 sessions/entries are verified prerequisites. There is no implemented planner repository, revision/request handling, recurrence engine, or YourDay view yet. Additional metadata must be additive and preserve ordinary/edited fixture data. All runtime database access must reuse the SQL-plugin pool and frontend Workspace mutation queue.
