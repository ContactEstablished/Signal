## Implemented scope

- Migration 3 adds `timer_sessions` and `timer_requests` to the existing SQL-plugin database. Partial uniqueness permits one running/paused session per task, concurrent across tasks. Original tables and time-entry fields remain intact.
- Start/Pause/Resume/Stop use UTC timestamps, integer milliseconds, transactionally prepared replies, durable request receipts, and the existing completed-entry hours-cache triggers. Stop finalizes the session and records one entry atomically. Manual Log uses the same accounting transaction.
- Running includes elapsed wall-clock time during sleep/app shutdown; paused excludes it. Negative current segments clamp to zero without erasing previously accumulated intervals. System clock corrections affect elapsed by the approved D2 policy. Display floors to HH:MM:SS without a 24-hour wrap; fractional minutes remain in storage. Zero-duration Stop is valid; manual Log must be positive.
- The existing Workspace queue serializes timer/log and M1 writes. Committed replies publish sessions, history, task totals, and revisions before refresh. Unknown IPC outcomes retain the exact request ID/payload for Retry, protect the affected task from other writes/deletion, and block editor/native closure. Confirmed Log receipt replay clears only its submitted form, once. Read failures keep known state.
- Task detail has explicit Start/Pause/Resume/Stop controls, separate active elapsed versus completed hours, local-date/start/duration Log form, timezone and ambiguous-DST offset selection, calculated end, future validation, overnight/overlap support, and read-only entry history. Dirty Log drafts participate in the existing editor exit guard.
- The header derives running count from live records; paused sessions are excluded. Native tooltip derives running/paused counts on initialization, transitions, and deletion. Minimal Open/Quit is retained. Timer-aware deletion previews warn about unlogged loss; confirmed deletion removes sessions/history/receipts in the same transaction. Display ticking alone does not change a preview fingerprint.
- All fixture consumers share one native-persisted clock offset. The per-second UI repaint does not increment stored elapsed time. Focus/visibility restoration ticks immediately and refreshes guarded state.
